Machine state

 DOS the DOS ROM is on
 SLOT0 SLOT1 SLOT2 SLOT3 which page is mapped into the memory window at #0000, #4000, #8000 and #C000 - the four rows of the MEMMAP panel. On a 128K SLOT3 is the page the 7FFD port put there, 0..7
 FRAME frames drawn since the last reset - a reset puts it back to 0
 RAYX RAYY where the beam is - the two numbers of the RAY panel. RAYY is the line, RAYX the dot in it, both counted from the first visible one, both including the borders. The line is longer than the picture: the retrace sits at its end, and on a ZX a dot is half a T-state, so a 48K frame is 448 x 312
 HITS on a breakpoint with an address: how many times that address has been hit, the current hit included and whatever the condition says - so HITS > 30 lets the first 30 hits pass and stops on the 31st. On a global condition there is no address to count, so it counts its own firings: HITS < 3 stops on the first three

Good to know

  • A breakpoint of type Condition (global) needs no address: it is checked after every instruction and stops while the expression is true - the way it reads, and the way a condition on an address breakpoint works. Tick On change to stop only when it becomes true instead.
  • Numbers follow the same rules as the assembler in the disassembler window: 100 is a hundred, 0x100 and #100 are 256, 0100 is 64. A bare BC or FF is therefore never a number - it is looked up as a register, a variable or a label, and hex always needs its prefix.
  • The line under the condition field shows how the expression was understood, with the priorities as brackets - worth a glance before pressing OK.
  • On a Fetch breakpoint the registers are read before the instruction, on Read/Write/IO ones after it.
  • Division by zero gives 0 and is not an error, so a condition doesn't start stopping everywhere when a divisor happens to be 0.
  • An address holds one breakpoint, so it has one condition. Join several with ||.
  • An expression that fails to evaluate stops the emulation, so a mistake in it can't go unnoticed.
  • HITS in a global condition can limit but not skip: the counter only moves when the condition fires, so (PC == 0x8000) && (HITS > 30) never becomes true - HITS waits for the condition and the condition waits for HITS. To let an address pass N times first, make it an address breakpoint at 8000 with the condition HITS > 30: there the counter moves on every hit.
  • A condition is checked between instructions and the beam moves 8 to 46 dots inside one, so an exact RAYX is stepped over: RAYX >= 14 && RAYX < 16 caught 1 frame out of 1025 here. Write it as RAYX >= 14 - true to the end of the line, impossible to miss. You stop on the instruction that starts at or after the point; the one the beam crossed it in is the row above, since knowing its length beforehand is not something a condition can do.
  • A Z80 port is 16 bits wide - IN A,(n) puts A on the high half, IN r,(C) puts B there - and ZX hardware only decodes a part of it. So IN and OUT hold the whole 16 bits, and (IN & 0xFF) == 0xFE is how you ask for "the keyboard port" instead of one exact address like IN == 0xFEFE. When the code does use a fixed value, as 7FFD paging does, plain OUT == 0x7FFD is enough.

Examples

 A == 5 && [SP] > 0xFF00 A is 5 and the stack is high
 (BC == 0x1234) || (BC == 0x5678) either value in BC
 M(PC) == 0x76 a HALT is about to be executed
 SP < 0x5B00 the stack ran away into the screen
 WR >= 0x4000 && WR < 0x5800 something is writing to the screen bitmap
 (IN & 0xFF) == 0xFE && VAL != 0xFF a key is being pressed
 (OUT & 0xFF) == 0xFD && (VAL & 7) == 3 RAM page 3 is being paged in at #C000
 SLOT3 == 7 RAM page 7 is mapped at #C000 - which page is shown is a different bit of 7FFD
 HITS == 30 on an address breakpoint: the 30th time that address is hit
 FRAME == 300 as a global condition with On change: the first instruction of frame 300
 RAYY == 100 every instruction of line 100; with On change, once a frame
 RAYY == 100 && RAYX >= 200 the same line, from dot 200 on
